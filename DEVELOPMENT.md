# WoW Chat Voice — заметки для разработки

Описание для игроков — в [README.md](README.md). Здесь — как всё устроено, почему так, и как проверять.

## Почему полоска пикселей

- WoW с 11.2 загружает только подписанные DLL голосов SAPI: сторонние голоса видны в списке озвучки игры, но молчат. Подписывать DLL и подкладывать их игре — не вариант (риск бана).
- Лог чата (`/chatlog`) игра пишет на диск только при выходе из мира.
- Аддоны не могут писать файлы во время игры. Остаётся экран: аддон рисует строку ячейками, программа снимает окно игры. Ничего не внедряется в процесс игры.

## Устройство

- `addon/WowChatVoice/` — аддон (WoW Forever, интерфейс 16001). Порядок загрузки — в `WowChatVoice.toc`.
  - `Protocol.lua` — кодирование строки в ячейки (чистые функции; тот же файл грузит тест через LuaJIT).
  - `Strip.lua` — полоска у верхнего края: очередь строк, удержание, пустой кадр.
  - `Dictionary.lua` — стандартный словарь (`D.DEFAULT`), слои (правки игрока поверх стандарта), окно словаря, сортировка, слой игрока для программы (`D.UserLayer`). Сам словарь применяет программа.
  - `Core.lua` — события чата, проверка «видно в окнах чата», сбор строки (`ns.Send`; имя отделяется меткой `\x04`, по которой программа отбрасывает его у следующей строки того же персонажа, пока предыдущая читается или закончилась не больше `same_speaker_gap` секунд назад — `protocol.without_repeated_name`, `Engines.quiet_for`: конец строки знает только программа), ожидание CatQuest (`ns.Deliver`: пока он читает квест — по неофициальному `CatQuestCore.state.playing`/`.pending` — строки ждут, старше 40 с выбрасываются; ставить квест на паузу нельзя — клиент не продолжает звук с середины, реплика начиналась бы заново), управляющие кадры, передача регулярок, `/wcv`.
  - `UI.lua`, `Options.lua`, `DictionaryWindow.lua`, `VoicesWindow.lua`, `Minimap.lua` — окна и значок.
  - `VoiceList.lua` — список голосов Windows; пишет программа (в репозитории — пустая заготовка).
  - `Icon.tga` — рисует `tools/make_icon.py` (`mise run icon`).
- `companion/` — программа для Windows (Python), пакет `wcv`, запуск `WowChatVoice.cmd` (создаёт `.venv`, ставит `requirements.txt` и `requirements-f5.txt`).
  - `__main__.py` — настройки по умолчанию (`DEFAULT_CONFIG`, дописываются в `config.json`), журнал, главный цикл: снимок → декодирование → разбор → текст → движок.
  - `window.py`, `capture.py` — окно WoW и его снимок; `protocol.py` — декодер полоски и разбор строки.
  - `dictionary.py` — словарь: стандарт прямо из `Dictionary.lua` аддона (перечитывается при изменении файла), слой игрока (частями по полоске, до этого из SavedVariables), слова, фразы, основы, регулярки, формы по числу, порядковые; `morph.py` — склонение замен после предлогов; `text.py` — ударения (RUAccent), числа словами с согласованием.
  - `engines.py` — какой движок читает строку, ленивая загрузка и выгрузка F5; `speech.py` — голоса Windows (SAPI); `f5engine.py` — F5-TTS; `intonation.py` — вопросительная интонация; `audio.py` — проигрыватель.
  - `gamevoices.py` — банк образцов из озвучки клиента игры по таблице `game_voices.json`; `casc.py` — чтение файлов из хранилища клиента (только чтение); `refcheck.py` — Whisper: текст реплик и проверка образцов; `assign.py` — распределение голосов; `voicelist.py` — `VoiceList.lua` для аддона; `launch.py` — запуск игры через Battle.net.
- `companion/tests/` — тесты (см. ниже).

## Конвейер текста

1. Аддон: разметка чата убирается (цвета, иконки; ссылка на квест или предмет — её название без скобок), «+» из чата становится словом «плюс» (дальше «+» — только ударение), пара скобок между буквами (`)(`, `}{`, `><`) — буквой «х» (так обходят фильтр мата), остальные скобки-смайлики — точкой. Имя персонажа перед строкой отделяется меткой: `\x04` (программа может его отбросить у продолжения речи) или `\x05` у эмоции (не отбрасывается); всё дальнейшее, включая словарь, работает только со строкой, не с именем.
2. Программа: маскированные слова (`unmask.py`): латинские двойники и цифры внутри русского слова — русскими буквами, слово со звёздочками — по списку частых нецензурных слов (в словаре pymorphy3 их нет). Затем слова, фразы (длиннейшие первыми) и основы словаря (`Dictionary.apply_words`); для склонения после предлога помечаются (`\x02…\x03`) только замены целых слов и фраз без `*` («в ОП»): у основы окончание взято из чата, падеж в нём уже правильный («на перекрёстке»), а правило «после в/на — винительный» сделало бы «на перекрёсток». Замены склоняются после предлогов (`morph.py`, если включено), затем регулярки словаря (их замены тоже помечаются и склоняются), формы по числу `N [a|b|c]` и порядковые `<N>`; затем `text.plain`: метка уровня квеста («[24]») убирается, оставшиеся скобки — пробелом, слова заглавными (2–5 букв), которых не раскрыл словарь: известное pymorphy обычное слово («ВСЁ», «СТОЙ») — строчными (иначе RUAccent ставит ударение как в аббревиатуре); аббревиатура или неизвестное — по буквам, если не произносится слогами (нет гласных, две согласных в начале, три подряд, две на конце у коротких: «ППС» — «пэ-пэ-+эс», «ЦРУ», «США»; начальный слог «согласная + гласная» читается слогом: «ГИБДД» — «ги-бэ-дэ-+дэ»), иначе как слово («ОМОН», «ВУЗ»); pymorphy помечает аббревиатуры (`Abbr`), но не говорит, как их читать.
3. Числа словами (`num2words`), согласованные со словом после числа через pymorphy3 (`text.agree`): для 1 — род и падеж слова, для 2 — род, в косвенных падежах множественного — падеж всего числительного. Слова, которых нет в словаре pymorphy3 (сленг), не трогаются: его догадка по окончанию часто неверна («2 дамагера» он считает женским родом). Порядковое вместо количественного (`text.ordinal`) — где подходит только оно: после числа существительное в единственном числе, в именительном или в падеже, которого требует предлог перед числом («с 15 уровня», «на 2 этаже»; количественному там нужно множественное). Слова, которые нумеруют, а не считают (`NUMBERED`: уровень, этаж, место, босс…), решают и неоднозначное: число на 1 («с 21 уровня»; а «по 1 золотому» — «одному») и родительный без предлога («хил 15 уровня»; а «200 опыта» остаётся количеством).
4. Ударения: словарные «+» главнее, остальное — RUAccent с учётом контекста (его разметка переносится в исходную строку по словам, сопоставленным по буквам, как diff: слово, которое он разбил по-своему, — «RU/UA», «<MIR>» — остаётся без ударения, а не вся строка); числа к этому моменту уже словами, поэтому и они получают ударения (иначе F5 сам ставил «ш+естнадцать»).
5. F5: строка делится на части — подряд идущие утверждения вместе, каждый вопрос отдельно; каждая часть синтезируется и получает свою интонацию, части склеиваются с паузой 0,15 с.

Порядок важен для правил с контекстом: регулярки видят текст уже после замен слов словаря. Например, «кд» к этому моменту уже «кулд+аун», поэтому правила секунд и серебра ждут оба варианта.

## Протокол полоски (версия 1)

- Ячейка — квадрат `cell` × `cell` физических пикселей (по умолчанию 2), ряд ячеек от левого верхнего угла клиентской области (`stripFrom = "left"`) или от правого (`"right"`); программа читает оба направления. Справа ячейки закрывает миникарта у верхнего края: она рисуется поверх любых фреймов, и длинные кадры обрезаются (пустой кадр помещается, поэтому «связь есть», а строки не читаются). `rows` рядов (по умолчанию 1).
- Под ячейками — чёрная полоса на всю ширину; ячейки почти чёрные, всё сливается в одну тёмную линию.
- Цвет ячейки — три канала по 4 уровня: 0, 12, 24, 36 (из 255), то есть 6 бит на ячейку. Ярче — заметнее в игре (цветные ячейки на 0–72 бросались в глаза); темнее — меньше запас по гамме: при гамме g уровень L становится 255·(L/255)^g, и при шаге 12 уровни различаются примерно до g = 1,2 (тест держит 1,1 и 1,2 с шумом).
- Ячейки 0–1: синхронизация (3,0,3) и (0,3,0). Ячейки 2–5: калибровка, все каналы на уровнях 0, 1, 2, 3 — программа берёт пороги посередине между ними, поэтому уровни можно менять только в аддоне.
- Дальше поток битов, старший первым: версия (4), номер строки (16), длина в байтах (12), CRC-16/CCITT-FALSE (16) по двум байтам номера и байтам строки, затем байты строки (UTF-8).
- Строка: `тип␟отправитель␟раса␟пол␟класс␟канал␟параметры␟текст[␟исходный текст]`, разделитель `\x1f`. Параметры — `rate=100;vol=100;voice=f5;decl=1;raw=1`: скорость и громкость в процентах, движок `f5`/`sapi`, склонение, есть исходный текст (он последним: при нехватке места обрезается он). Пол 2 — мужской, 3 — женский. Служебные типы: `control` (настройки: движок, выключенные голоса Windows `off=`), `dict` (часть слоя правок словаря игрока: `id=;part=;of=`), `diag` (пометка в журнал программы: что аддон выбросил), `pause`/`resume` (CatQuest заговорил / замолчал: проигрыватель обрывает строку и на `resume` играет её заново с начала, потом очередь; кадр встаёт в начало очереди полоски — `Strip.PushFirst`; без `resume` пауза снимается сама через 90 с), `stop`, `reset`; неизвестные типы программа не читает вслух.
- Строка держится не меньше 0,25 с (программа снимает окно 20 раз в секунду), через 0,5 с без новых строк полоса возвращается к пустому кадру (14 ячеек). Номер строки при загрузке аддона случайный: программа пропускает то, что было на полоске до её запуска.
- Слой правок словаря игрока идёт кадрами до 480 байт с контрольной суммой слоя: при входе в игру и через 2 с после правки. Раз в 2 минуты аддон шлёт короткий кадр настроек, а слой — только если он менялся в этой сессии: иначе программа, запущенная позже игры, прочтёт тот же слой из SavedVariables (`dictionaryUser`), а каждый такой кадр — черта на полэкрана.
- Диагностика: декодер различает «полоски нет» и «полоска есть (синхронизация и калибровка на месте), но кадр не сходится» (`protocol.last_failure`); второе дольше секунды — запись в журнал.

## Словарь на слоях

- Стандарт (`D.DEFAULT`) живёт в аддоне; в SavedVariables — только правки игрока, `dictionaryEdits = { lines = { [ключ] = "блок" }, removed = { [ключ] = true }, header = "…" }`: изменённые и свои записи с комментариями над ними, пометки «удалено», шапка, если менялась. Итог (`D.Text()`) — стандарт с правками, отсортированный; окно словаря показывает итог, а при правке `D.SetText` считает разницу со стандартом.
- Ключ записи (`D.KeyOf`): у слов — нормализованные слова (`*` для основы), у регулярки — шаблон (всё до последнего `=`), так что правка замены — та же запись.
- Обновление аддона ничего не мигрирует: нетронутые записи получают новый стандарт, правленые остаются, удалённые не возвращаются, новые появляются. Если меняется шаблон стандартной регулярки (ключ), старый → новый ключ записывается в `D.RENAMED`: у правившего или удалившего старую новая рядом не появится.
- Применяет словарь программа (`dictionary.py`): стандарт она читает прямо из `Dictionary.lua` в папке аддона и перечитывает, как только файл меняется — правка стандарта работает через секунды, без `/reload` (клиент читает файлы аддона только при его загрузке, а программа может читать их когда угодно). Правки игрока аддон шлёт слоем (`D.UserLayer`: изменённые и добавленные строки, `!<строка стандарта>` для удалённых — строка, не ключ, чтобы ключ программа считала сама и расхождения в нормализации Lua и Python не мешали) и кладёт в SavedVariables (`dictionaryUser`) для программы, запущенной без игры. Окно словаря и слои остаются в аддоне.
- Сортировка: русские записи по алфавиту, латиница, цифры и символы, регулярки в конце; комментарии переезжают с записью под ними, верхний блок — шапка. `D.Text()` собирает блоки сам: `D.Sort` считает шапкой все комментарии до первой записи и прихватил бы комментарий случайного первого блока.
- Задел: стандарт с GitHub как слой между встроенным и правками — раз словарь применяет программа, скачанный стандарт она может брать сразу, без файла в папке аддона и без `/reload`. Нужны `D.RENAMED` вместе со словарём и проверка регулярок при загрузке (компиляция, длина, прогон с таймаутом — от катастрофического перебора).

## F5-TTS и банк голосов

- Модель `Misha24-10/F5-TTS_RUSSIAN` (`F5TTS_v1_Base_v2`, CC BY-NC), `nfe_step` 16: около 0,8 с на строку на RTX 5070 Ti, около 2 ГБ видеопамяти. Синтез и воспроизведение в разных потоках. F5 загружается сразу при запуске программы, пока запускается игра (если в сохранённых настройках аддона не выбраны голоса Windows), и выгружается при выборе голосов Windows.
- F5 клонирует голос по образцу (5–10 с записи и её точный текст) при каждом вызове. Образцы делаются из русской озвучки клиента (см. «Голоса из клиента игры») и хранятся в `voices/` с номером сборки игры, из которой сделаны.
- Длина фразы: `fix_duration` = образец + строка × `f5_margin` (1,25) + `f5_tail` (0,5 с) — без запаса F5 обрезал последние слоги (на 40 фразах 10 голосов: 14 обрезанных без запаса, 0 с ним).
- Темп задаём мы: F5 укладывает речь ровно в данную длину (`fix_duration`), поэтому длина и есть темп (`f5engine.line_seconds`). Темп голоса — речь образца без пауз между его репликами на байт текста (`Slot.speech`; с паузами голос из коротких реплик говорил на 40–50 % медленнее). Образцы из клиента различаются по темпу почти втрое (16 букв/с у фраз ошибок персонажа против 5,5 у торжественных приветствий NPC), поэтому голос медленнее быстрой четверти банка (`voice_pace_quantile` 0,25 — ближе к голосам персонажей; медиана — типичный NPC, сама неспешная) подтягивается к ней в геометрическом среднем на `voice_pace_blend` (0,85), не больше чем в `voice_pace_limit` (1,8) раза; быстрые не трогаются. Выбрано на слух из четырёх вариантов (тестовая строка: таурен-старейшина 18,5 с как в записи, 14,7 — к медиане на полпути в обе стороны, 12,9 — к медиане только медленные, 12,3 — к быстрой четверти). Каждому персонажу — свой темп в пределах ±`character_tempo` (8 %, от crc32 имени): двое с одним голосом звучат как двое. Ползунок скорости аддона — сверху; `f5_margin`/`f5_tail` — запас, чтобы не сжимать последние слоги.
- Обрыв концовки: F5 случаен, и примерно каждая десятая фраза доходит речью до самого конца данной длины — последний слог не влез. Если тишины после последнего звука меньше 0,06 с (`silence_after`), фраза синтезируется ещё раз с длиной на 25 % больше: на трёх голосах, где обрыв было слышно, обрывов стало 1 из 60 вместо 6 из 60 (повтор понадобился 6 раз). Длинный хвост (0,8 с вместо 0,5) и тишина после образца не помогли (10 из 60): F5 растягивает речь на всю данную длину.
- Разнообразие: 4 голоса на расу и пол плюс копии каждого со сдвигом тембра (`voice_shifts`, ±1,5 полутона, передискретизацией образца). Распределение с памятью (`assignments.json`, `assign.py`): новому персонажу — наименее занятый голос среди слышанных за 30 минут, сначала сами голоса, потом копии. Файл не растёт бесконечно и не пишется на каждой строке: при запуске забываются персонажи, которых не было слышно 60 дней (`FORGET`; вернувшийся получит голос заново — тот же, если голосов хватает: порядок выбора задан именем), запись — не чаще раза в 30 с (`SAVE_EVERY`), при выходе (`atexit`) и выгрузке F5, через временный файл (убитый посреди записи процесс оставит старый файл, а не половину нового). SQLite не нужен: ни запросов по истории, ни нескольких писателей, а прикидка для шумного сервера — порядка мегабайта. Расы, которых нет в банке, — по родственным (`RACES` в `assign.py`).
- После синтеза (и для голосов Windows): тишина перед речью обрезается (остаётся 50 мс), громкость выравнивается одним множителем на фразу (~−22 дБ, пик не выше 0,95 — интонация не меняется), крик +3 дБ, шёпот −4 дБ (`kind_gain_db`), громкость аддона (до 200 %) с мягким ограничением пиков выше 0,8 (`f5engine.limit`).
- Обходы: `torchaudio.load` через `soundfile` (torchaudio 2.11 декодирует через `torchcodec`, которому нужны DLL FFmpeg); нулевые `token_type_ids` для ONNX-моделей RUAccent. torch закреплён `==2.11.0+cu128` (иначе pip ставит CPU-сборку). Модели после первой загрузки берутся из кэша без сети (`.models_ready` → `HF_HUB_OFFLINE`).

## Голоса из клиента игры

- Источник — русская озвучка в файлах клиента: на каждую расу и пол голос персонажа (`sound/character/<раса>/…errormessages` — спокойные фразы вроде «Недостаточно маны», и эмоции: приветствие, спасибо, да, нет…) и три типа NPC (`sound/creature/<раса><пол><тип>npc`: приветствия, прощания, фразы торговца и раздражённые). Боевые выкрики не берутся. В клиенте Forever есть и ритейловые расы (эльфы крови, дренеи, гоблины, воргены, пандарены, союзные расы) — задел на ритейл.
- `companion/wcv/game_voices.json` — какие это файлы: номера файлов (FileDataID, они не меняются между сборками) с типом реплики и приоритетом (1 — спокойная речь, 2 — эмоции, 3 — шутки и раздражённые). Собирается `tools/game_voices.py` (`mise run voices-table`) из общего списка файлов [wowdev/wow-listfile](https://github.com/wowdev/wow-listfile); в таблице только номера, никаких данных игры.
- `casc.py` читает хранилище CASC установленной игры: `.build.info` (активная сборка продукта: `wowf` у Forever, по `_forever_/.flavor.info`) → конфиг сборки → локальные индексы → BLTE-блоки в `Data/data/data.NNN`; таблица encoding — ключ содержимого → ключ данных, таблица root — номер файла и язык → ключ содержимого. Русская версия файла — запись с флагом ruRU без флага enUS (запись для всех языков — общая английская). Только чтение, стандартная библиотека; работает и при запущенной игре (2491 файл за ~4 с), но банк собирается до запуска игры: пока Battle.net обновляет клиент, архивы меняются. Установку игры программа ищет так, чтобы папка `_forever_` существовала и её продукт был в `.build.info` (на одном компьютере может быть несколько установок на разных дисках).
- Сборка банка (`gamevoices.build`): реплики голоса — по приоритету; Whisper large-v3-turbo распознаёт их по одной, пока спокойной речи не наберётся с запасом; отсеиваются галлюцинации (`plausible`: «Продолжение следует…», латиница, смех, неправдоподобная скорость речи — короткий выкрик «Заг-заг» Whisper слышит как целую фразу). `choose` берёт до 4 реплик на 5,5–9,5 с речи, не больше одного вопроса, последней — утверждение; реплики склеиваются с паузой 0,15 с на одной громкости; склейку снова слушает Whisper — сходство с текстом не ниже 0,8, иначе самая короткая реплика заменяется. Меньше 3 с годной речи — голос пропускается.
- Банк хранится в `voices/bank.json` с отметкой: версия банка, установка, продукт, номер сборки игры, `voice_shifts`, размер таблицы. Отметка совпала — банк берётся как есть, без Whisper; изменилась (игра обновилась) — собирается заново: при запуске программы до запуска игры (`f5engine.prepare_voices`) или, если игра уже запущена, при загрузке F5.
- Риск бана: античит следит за процессом игры (чтение и запись его памяти, внедрение, автоматизация ввода); чтение файлов на диске игру не затрагивает — так работают wow.export, WoW Model Viewer и датамайнинг-сайты. Звук принадлежит Blizzard: банк делается только на компьютере игрока и не распространяется.

## Интонация вопросов

- F5 сам вопросительной интонации почти не делает. Прогон 20 вопросов × 4 голоса: подъём ≥ 2 полутонов в конце да/нет-вопроса — в 5 % случаев, и с «?», и с точкой (знак вопроса модель не учитывает); `??`, `?..`, `cfg_strength` 3–4 не помогают; лучший из трёх seed находит подъём в 22 % случаев. Вопросы с вопросительным словом F5 в основном и так роняет к концу (68–85 %) — для них это правильно.
- Образцы с вопросом в конце не помогли ни с синтезированными голосами CatQuest, ни с живыми записями из клиента (у чистых голосов конец да/нет-вопроса в среднем −5,6 и −1,8 полутона против −4,9 и −4,2 у CatQuest): русский F5 вопросительную интонацию из образца не переносит.
- Поэтому `intonation.py` (Praat PSOLA через `praat-parselmouth`: меняется тон, тембр и темп нет), `question_intonation` в `config.json`:
  - да/нет-вопрос («Идёшь с нами?»): последние 0,45 с голоса поднимаются до +7 полутонов над медианой реплики (`yes_no_rise_st`); последний слог, если F5 его погасил («гру-ппу»: «-пу» после смычки на 15–20 дБ тише), поднимается до уровня на `yes_no_end_db` (8) дБ ниже громких мест (90-й перцентиль громкости по 10-мс кадрам);
  - вопрос с вопросительным словом («Кто идёт?», «Ну а где танк?», частицы в начале пропускаются, «кто-нибудь» — не вопросительное слово): пик +6 полутонов на вопросительном слове (`wh_peak_st`), конец не трогается. Место слова — по номеру его ударного гласного среди гласных реплики в отрезке звучания; против Whisper ошибка около 0,12 с, поэтому пик широкий (0,16 с) и поднимает всё слово.
  - Пробовали и отказались: занижение начала да/нет-вопроса (на слух не отличается), растяжка конца (не слышна — дело было в громкости), подъём на первом слове вместо конца.
- Диапазон анализа тона подстраивается под реплику (`pitch_range`: медиана по 40–1200 Гц, пол — в 2,5 раза ниже, но не ниже 40 Гц, потолок — в 2,2 раза выше, не ниже 500 Гц). С постоянными 60–500 Гц анализ терял периоды с обеих сторон: у гномих (450–500 Гц, у NPC до половины речи выше 500) и у орка-персонажа (55–70 Гц; замер от 75 Гц брал октаву выше), и перестроенный голос хрипел; тест `HighVoices` ловит оба края. Рычащие голоса (орки-NPC guard и shady) остаются трудными: тон в них неоднозначен и для замера, и для PSOLA.
- Только для F5; без parselmouth звук не меняется.

## Голоса Windows (SAPI)

- pywin32, синтез в память (`SpMemoryStream`, 22 кГц 16 бит моно), проверка на обрезанный звук по длине текста.
- Голос игрока — рандеву-хешированием по имени и полу (у кого больше хеш пары «имя + голос»): выключение голоса меняет голос только у его игроков.
- Ударения — как принимает каждый движок (`stress`): RHVoice — U+0301, Silero — «+», Edge — без ударений (читает «+» вслух и не понимает U+0301).
- Строки латиницей без кириллицы — английскими голосами Windows.

## Захват

- Windows Graphics Capture (`windows-capture`) по окну игры: работает, когда окно закрыто другими; смещение клиентской области — через `DwmGetWindowAttribute`. Без него — снимок экрана `mss` (игра должна быть сверху). Свёрнутую игру не видит ни один способ.
- Проверять захват можно только в сессии пользователя: из SSH снимок экрана запрещён и окон нет.

## Инструменты и тесты

Инструменты разработки — через [mise](https://mise.jdx.dev/): `.mise.toml` закрепляет точные версии Python, uv и LuaJIT. Библиотеки для тестов и значка — группа `dev` в `pyproject.toml` (проект uv без пакета: версия аддона только в `.toc`), точные версии — в `uv.lock`. По [рекомендации mise для uv](https://mise.jdx.dev/lang/python.html) uv берёт Python из mise (`UV_PYTHON`), а `.venv` mise создаёт через uv и активирует сам (`python.uv_venv_auto`). После клонирования: `mise install`. Задачи (`mise tasks`):

- `mise run test` — все тесты: Python (с numpy, pymorphy3, num2words — ни один не пропускается) и Lua;
- `mise run test-py`, `mise run test-lua` — по отдельности;
- `mise run icon` — перерисовать `Icon.tga` и `tools/icon_preview.png`;
- `mise run voices-table` — пересобрать `companion/wcv/game_voices.json` из общего списка файлов игры (`tools/game_voices.py`; список скачивается в `tools/.cache/`).

Программе у игрока mise не нужен: на Windows её ставит и запускает `WowChatVoice.cmd`.

- `test_protocol.py` — кодировщик аддона (через LuaJIT) → отрисованная полоса (гамма, шум, ячейки 1–4 px, два ряда, полоса справа, перекрытая полоса) → декодер программы.
- `test_gamevoices.py` — банк из клиента: BLTE, таблица root, продукт игры, отсев галлюцинаций Whisper, выбор реплик для образца, кэш по номеру сборки, таблица голосов (у каждой расы и пола не меньше 4 голосов).
- `test_logic.py` — ударения, распределение голосов, разбор строки, регулярки, громкость, ограничитель, вопросы, согласование чисел; `test_morph.py` — склонение; `test_engines.py` — выбор движка. Без numpy, pymorphy3 и num2words часть тестов пропускается — поэтому запускать через `mise run`.
- `ui_mock.lua` — все окна аддона на заглушках WoW API, строки полоски, чтение только видимого в окнах чата, настройки переживают открытие окна.
- `dictionary_layers.lua` — слои словаря: ключи, правки, удаления, новый стандарт, переименование шаблона.

## Проверка на Windows

Разработка шла на Mac, проверка — на Windows-машине с игрой по SSH. Раскладка: файлы `addon/WowChatVoice/` (кроме `VoiceList.lua`, его пишет программа) — в `Interface\AddOns\WowChatVoice\` клиента, `companion/wcv/*.py` — в папку программы. Аддон подхватывает изменения после `/reload`, программа — после перезапуска. PowerShell-команды — файлом через `-File` (Defender блокирует `-EncodedCommand`).

## Исследования

- **XTTS v2** (кандидат для других языков): одна модель на 17 языков, клонирует без текста образца, потоковый синтез (первый звук ~0,47 с против ~1,1 с у F5). Минусы: нет управления ударением (частично спасает дефис: «Ко-пи деньги»), бормотание после конца фразы, лицензия CPML. Для русского F5 лучше: ударения через `+`. Fish Speech и Vosk TTS не подошли.
- **Образцы из клиента против CatQuest** (до 0.2.0 банк делался из голосового пака CatQuest, а его голоса сами синтезированы F5 и Eleven v4): с живыми записями тембр ближе к образу (орк ~80–100 Гц против 190–280), разборчивость выше (сходство с текстом по Whisper 0,90 против 0,87; у орка CatQuest искажал слова). В ритейле в клиенте есть ещё озвученные диалоги с точным текстом в `BroadcastText` — источник для ритейловых рас.
- **Пунктуация перед синтезом**: в чате вопрос часто без «?», и тогда ни разбиение, ни интонация вопроса не срабатывают. Правило — только добавлять знаки, не исправлять. Варианты от дешёвых к дорогим: правила (вопросительное слово в начале, частица «ли»), RUPunct_small (BERT, MIT, есть INT8 ONNX), RUPunct_medium/big, Silero TE, `sbert_punc_case_ru`, маленькая языковая модель. Сравнить на базе строк `исходно:` из журналов с ручной разметкой: доля верно поставленных «?», ложные «?» на утверждениях, запятые отдельно, время и память.
- **ElevenLabs** как необязательный облачный движок: хороший русский и мгновенное клонирование по тем же образцам; минусы — платно (живой чат — десятки тысяч символов за вечер), чат уходит на сервер, нужна сеть.
