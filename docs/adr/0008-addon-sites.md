# 0008. Аддон на CurseForge и Wago Addons: выпуск собирает и выкладывает BigWigsMods/packager

Статус: предложено (20.11.2026, после 0.4.0 beta 23).

## Контекст

Аддон ставит и обновляет лаунчер ([0003](0003-per-user-installer.md), [0004](0004-signed-updates.md)), но игроки ищут аддоны на CurseForge (самый большой каталог, свой фильтр Forever, версия игры 1.60.1) и на Wago Addons (каталог WowUp и приложения Wago). Там Barrens Voice никто не найдёт. Аддон лежит в `addon/BarrensVoice` репозитория программы, а не в его корне, как ждут оба сайта. На CurseForge уже лежат аддоны с внешней программой (например, wow-ai), так что это не препятствие.

## Решение

Выпуск (`vX.Y.Z`, не тестовая сборка) после выпуска на GitHub выкладывает аддон на оба сайта: задание `addon-sites` в `release.yml` (workflow `addon-sites.yml`) запускает [BigWigsMods/packager](https://github.com/BigWigsMods/packager) (v2.7.0, закреплён по коммиту: с 2.6 знает Forever, интерфейс `16xxx`). `.pkgmeta` берёт из репозитория только аддон: `move-folders` переносит `addon/BarrensVoice` в корень zip как `BarrensVoice`, остальное в `ignore`. Версии игры packager берёт из `## Interface` (16001 — Forever, 120105 — ритейл). Перед ним `tools/addon_sites.py` ставит в `Dictionary.lua` ту же ревизию, что в архиве выпуска (`release.stamp_dictionary`), и пишет журнал изменений файла: запись выпуска из `news.toml` и строку о том, что аддону нужен Barrens Voice Launcher, со ссылкой на выпуск на GitHub. Проекты на сайтах называют переменные репозитория `CF_PROJECT_ID` и `WAGO_PROJECT_ID`, выкладывают секреты `CF_API_TOKEN` и `WAGO_API_TOKEN`; пока переменных нет, задание пропускается. CI на каждом пуше вызывает тот же workflow без тега: zip собирается без выкладки и проверяется (аддон и ничего больше, zip хранится неделю), а токен CurseForge, если задан, пробуется на списке версий игры — первом запросе packager, в нём должна быть Forever. У Wago такого запроса нет: его проект и ключ проверит только первая выкладка. Неудачную выкладку выпуска можно повторить руками (запуск `addon-sites.yml` с тегом), без нового выпуска.

## Альтернативы

- **Свой код выкладки по API сайтов.** Архив выпуска у нас уже свой, но версии игры CurseForge — его внутренние номера, у Wago — свои поля; packager это знает и обновляется вместе с сайтами. Своё пришлось бы чинить после каждого их изменения.
- **Аддон в отдельном репозитории.** Корень — сам аддон, packager без `.pkgmeta`; но аддон и программа меняются вместе (протокол полоски, тесты на Lua из Python), два репозитория разъехались бы.
- **Тестовые сборки тоже (тип «beta» на сайтах).** Тестеры получают их через тестовый канал лаунчера; на сайтах бета без лаунчера той же версии только путает. Можно включить позже, если понадобится.
- **Только CurseForge.** Wago — каталог WowUp и приложения Wago, у части игроков CurseForge нет. Выкладка туда — одна переменная и один секрет.

## Последствия

- Аддон с сайта без лаунчера молчит: это сказано в описании проекта и в журнале изменений каждого файла.
- Номер аддона и тег выпуска расходятся (аддон 0.4.0, тег v0.4.0 — сейчас совпадают, [0005](0005-separate-versions.md)): на сайтах файл называется по тегу программы.
- Обновление с сайта заменяет папку аддона целиком, вместе с файлами, которые пишет компаньон (`VoiceList.lua`, `CompanionStatus.lua`, `DictionaryOnline.lua`, `NewsData.lua`), — на заглушки из zip. Компаньон пишет их заново при старте, а игра читает при входе и `/reload`. Игра, запущенная после такого обновления раньше лаунчера, до `/reload` не видит списка голосов Windows и онлайн-словаря (до его обновления действует словарь аддона той же ревизии), а «Что нового» покажет при следующем входе: без `NewsData.lua` аддон не двигает `seenVersion` (`News.Prepare`). Приветствие не повторяется: первый запуск — это отсутствие `BarrensVoiceDB` в сохранённых переменных (`WTF`), а не в папке аддона. Лаунчер заменяет только аддон старее своего (`addons_to_update`), более новый с сайта остаётся.
- Проекты на сайтах заводятся руками (описание, картинки, модерация), до этого задание пропускается.
