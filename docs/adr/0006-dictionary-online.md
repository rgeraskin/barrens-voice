# 0006. Словарь онлайн: подписанный файл в отдельной ветке, побеждает более новая ревизия

Статус: принято (17.11.2026, 0.4.0).

## Контекст

Словарь сленга правится чаще, чем выходит программа. Хочется, чтобы новые слова доходили до игроков без выпуска. Словарь исполняется программой (регулярные выражения на каждой строке чата), поэтому брать его откуда попало нельзя.

## Решение

CI после зелёных тестов на master собирает `dictionary.json` из `Dictionary.lua` аддона, подписывает ключом выпусков и кладёт в ветку `dictionary` (только когда словарь изменился). Программа берёт его с `raw.githubusercontent.com` при запуске и раз в час, принимает только с верной подписью, своим форматом и быстрыми регулярками (проверка в отдельном процессе с таймаутом) и хранит последний принятый для запуска без сети. Стандартом становится более новый из двух — скачанный или пришедший с аддоном — по ревизии: времени последнего коммита, менявшего `Dictionary.lua` (её же сборка выпуска пишет в `D.REVISION`). В окно словаря в игре он попадает файлом `DictionaryOnline.lua` после `/reload`. Правки игрока — по-прежнему отдельный слой поверх стандарта.

## Альтернативы

- **Только с выпуском программы.** Слова доходят медленно.
- **Файл в ассетах выпуска или на своём сервере.** Ассеты привязаны к выпуску; свой сервер — лишняя инфраструктура. Ветка на GitHub бесплатна и обновляется из CI.
- **Минимальная версия программы в файле.** Новый вид записи, который старая программа прочтёт неправильно, — это смена формата, как у протокола полоски. Один номер формата проще двух проверок.
- **Без подписи.** Регулярки исполняются у всех игроков — подмена файла дала бы зависание или хуже.

## Последствия

- GitHub отдаёт файлы ветки через CDN с кэшем до 5 минут, и программа проверяет раз в час: новое слово доходит не сразу.
- Файл подписывается так, как его отдаёт GitHub: байтами с `\n` на любой системе (на раннере Windows подпись не сходилась из-за `\r\n`).
- При запуске из исходников словарь онлайн выключен — там правят сам `Dictionary.lua`.
