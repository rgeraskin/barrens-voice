# 0005. Раздельные номера программы и аддона, выпущенный номер неизменен

Статус: принято (17.11.2026).

## Контекст

Один выпуск (тег) на весь проект и один CHANGELOG. Аддон приходит к игроку внутри выпуска программы, а позже будет и на CurseForge и Wago. Лаунчер заменяет аддон в игре, только если его версия старше своей. В beta 1–9 аддон менялся под прежним номером 0.3.0 — и до игры так и не дошёл.

## Решение

- У программы свой номер (`pyproject.toml`), у аддона свой (`## Version` в `.toc`). Номер аддона растёт, только когда меняется аддон, и не обязан совпадать с номером программы.
- Выпущенный номер аддона неизменен: один номер — одно содержимое во всех выпусках, тестовые тоже. Изменили аддон после выпуска — номер поднимается до следующего. Это проверяет тест `AddonVersion` по всем тегам.
- Тестовые сборки несут тестовые сборки аддона (`0.4.0b1`, `0.4.0b2`…), выпуск — чистый номер. `0.4.0b2 < 0.4.0`, так что выпуск заменяет бету у тестеров. `tools/release.py` не соберёт выпуск с бета-аддоном.

## Альтернативы

- **Единый номер для программы и аддона.** Проще для игрока: одно число везде, и не нужно помнить о номере аддона. Но CurseForge узнаёт установленный аддон по отпечаткам файлов, а не по номеру: при едином номере `.toc` меняется с каждым выпуском программы, и пришлось бы выкладывать на CurseForge аддон без изменений при каждом выпуске — иначе у игрока он «Modified», и CurseForge перестаёт его обновлять.
- **Замена аддона той же версии, если файлы другие.** Номер перестаёт значить содержимое — отвергнуто.

## Последствия

- Новый аддон всегда означает и новый выпуск программы (аддон едет в нём), обратное — нет.
- Игрок видит в игре номер аддона, отличный от номера программы.
- На CurseForge выкладывается только выпуск, где поднят номер аддона, — ровно те файлы, что в архиве выпуска (update-strategy, «Этап CurseForge и Wago»).
