# 0004. Обновления с GitHub Releases по подписанному описанию выпуска

Статус: принято (17.11.2026, 0.4.0).

## Контекст

Программа должна обновляться сама. Ставить чужой код на тысячи машин опасно: подменённый выпуск или аккаунт стал бы вирусом у всех.

## Решение

Выпуск на GitHub несёт архив, `manifest.json` (версии программы, аддона и протокола, имя, размер и SHA-256 архива, версия и адрес uv) и подпись ed25519. Публичный ключ — в программе, закрытый — в секретах CI. Лаунчер проверяет выпуски при запуске и раз в час, ставит только то, что сходится с подписью, переключается без игры (или по «Установить сейчас») и откатывается, если новая версия дважды падает на старте. Тестовые сборки — pre-release с тегом `vX.Y.Z-beta.N`, их получает тот, кто включил «Получать тестовые версии». Код обновления, который уже стоит у игроков, проверяется тестами: новый выпуск должен ставиться через копии старых клиентов (`tests/compat`).

## Альтернативы

- **Без подписи, только HTTPS и SHA-256 из описания.** Защищает от порчи по дороге, но не от подмены выпуска.
- **Подпись установщика (Authenticode) вместо своей.** Нужна отдельно от SmartScreen, но обновления ставят архив, а не установщик, и проверять Authenticode из Python сложнее.
- **Свой сервер обновлений, CurseForge.** Лишняя инфраструктура; CurseForge не возит программы.

## Последствия

- Потеря закрытого ключа — новый ключ только с новым выпуском программы, который ставят руками.
- Старые клиенты должны уметь ставить новые выпуски — правило в CLAUDE.md и тест `OldClients`.
