# Установщик и обновления — решения (17.11.2026)

Как Barrens Voice ставится, обновляется и выпускается. Статус: согласовано, не сделано.

## Раскладка

```
%LOCALAPPDATA%\Programs\BarrensVoice\      программа: её меняет только обновление
  BarrensVoice.exe     маленький запускатель, почти никогда не меняется
  uv.exe               ставит Python и библиотеки
  python\              Python из uv (python-build-standalone: в нём есть tkinter)
  versions\0.4.0\      наш код и его окружение (.venv)
  versions\0.4.1\
  current.txt          «0.4.1»
<папка данных>                             обновление её не трогает
  config.json, assignments.json, voices\, logs\, кэш моделей (hf)
```

- Установка — для одного пользователя, без прав администратора (автозапуск через HKCU уже так и сделан).
- Папка данных по умолчанию — `%LOCALAPPDATA%\BarrensVoice`; установщик показывает её со свободным местом и, если на C: меньше ~8 ГБ, предлагает диск, где стоит WoW.
- Переезд старой установки (папка с `BarrensVoice.cmd`) не делаем: чистая установка заодно проверит, что значения по умолчанию совпадают с рабочим `config.json`.
- Удаление спрашивает, удалять ли данные (модели — гигабайты).

## Python и библиотеки — uv

- Компаньон переезжает с `requirements.txt` на `pyproject.toml` + `uv.lock` (проект, а не пакет в реестре: наш код ставится из папки версии).
- CUDA и DirectML — взаимоисключающие варианты (`[tool.uv] conflicts`): `--extra cuda` / `--extra directml`. Выбор — по видеокарте (NVIDIA → CUDA), без вопроса игроку; скрытый ключ `--runtime directml` — для проверки DirectML на NVIDIA.
- Обычный `onnxruntime`, который тянут RUAccent (и потом `piper-tts`), вычищается `override-dependencies`, а не руками в `BarrensVoice.cmd`.
- `exclude-newer = "7 days"` в `[tool.uv]` — включить при переезде на `pyproject.toml`: свежая версия пакета попадает к нам через неделю (защита от подменённых выпусков на PyPI); срочное исправление — исключением `exclude-newer-package`. У игрока установка с `--frozen` берёт версии из lock-файла и от срока не зависит.

## Обновление

- Новая версия ставится целиком в `versions\X`: `uv sync --frozen --no-dev --extra …` с окружением в этой папке. Библиотеки берутся из кэша uv жёсткими ссылками — 1,9 ГБ CUDA не качаются заново, если их версия не менялась. Потом меняется `current.txt`. Лишнее не нужно удалять по файлам: старая папка удаляется целиком после успешного запуска новой.
- Откат: новая версия не стартует (компаньон дважды падает при запуске) — запускатель возвращает предыдущую и говорит об этом.
- Не во время игры: версия готовится в фоне, переключение — при следующем запуске лаунчера или после закрытия игры (компаньон читает чат).
- Аддон в игре: игра закрыта — файлы заменяются молча; запущена — заменяются, и лаунчер пишет «в игре нужен /reload». Аддон новее нашего (поставлен с CurseForge) не откатывается.
- Галочка «Обновлять автоматически» (по умолчанию включена). Выключена — лаунчер показывает «Вышла версия X — Что нового / Обновить», кнопка делает то же самое. При смене протокола говорит прямо, что без обновления озвучка не работает.
- Проверка — при запуске лаунчера и раз в час. Стабильный канал — `releases/latest/download/manifest.json` (обычная загрузка, без лимита API); тестовый — список выпусков через API (60 запросов в час без входа).
- Тестовый канал: выпуски GitHub с пометкой pre-release (тег вида `v0.5.0-beta.1`; CI помечает тег с дефисом сам). В настройках лаунчера — «Получать тестовые версии». Сняли галочку — остаёмся на тестовой до стабильной, которая новее (без отката).

## Версии

- Совместимость решает номер протокола полоски (сейчас 1), а не номера версий: аддон сообщает свой протокол, компаньон знает, какие понимает. Вынужденное обновление — только при смене протокола.
- Один выпуск (тег `vX.Y.Z`) на весь проект, одна история изменений. Версия аддона в `.toc` поднимается только если менялся сам аддон (CI сравнивает папку аддона с прошлым выпуском) — тогда лаунчер не просит `/reload` из-за правок одного компаньона.
- Номера версий даются при выпуске; в README — этапы (Roadmap), а не версии.

## Выпуск (CI)

- Каждый шаг CI — задача mise (`mise run test`, `mise run build`, `mise run installer`…), которая так же запускается локально; workflow GitHub только ставит mise (`jdx/mise-action`) и вызывает эти задачи. Установщик (Inno Setup) собирается только на Windows: локально — на тестовой машине.
- GitHub Actions, только раннер Windows (компаньон — только для Windows; стандартные раннеры бесплатны для публичных репозиториев): тесты Python и Lua на каждый push.
- На тег: архив `barrens-voice-X.Y.Z.zip` (код, аддон, `pyproject.toml`, `uv.lock`), `manifest.json` (версия, протокол, версия аддона, SHA-256) с подписью ed25519 (публичный ключ — в лаунчере, закрытый — в секретах CI), установщик (Inno Setup), выпуск на GitHub с разделом CHANGELOG.
- Если менялся аддон — загрузка на CurseForge и Wago (упаковщик BigWigs, `.pkgmeta`). У Forever на CurseForge своя версия игры (1.60.1). Аддон, которому нужна внешняя программа, на CurseForge допустим: так устроены ForeverDubbed и AI Agents Chat.
- Словарь онлайн: после тестов на master CI кладёт `dictionary.json` (с подписью и номером формата, минимальной версией компаньона) в отдельную ветку `dictionary`; компаньон читает его с `raw.githubusercontent.com/rgeraskin/barrens-voice/dictionary/dictionary.json`. Подпись нужна: регулярки словаря исполняет компаньон.

## Подпись установщика

- После этапа «Распространение»: бесплатный SignPath Foundation для open source (MIT, публичный репозиторий, сборка в GitHub Actions, двухфакторная защита, раздел «Code signing policy» в README). Издателем в Windows будет «SignPath Foundation». Каждый выпуск подтверждается вручную — их условие (щелчок в письме или через их API, не из CI).
- Спросить в заявке: модели (F5, CC BY-NC) в установщик не входят и скачиваются отдельно — проходит ли это требование «без проприетарных компонентов».
- SmartScreen может предупреждать и с подписью, пока у файла нет репутации.

## Когда-нибудь

- **Установка для всех пользователей Windows** (семейный компьютер): программа в Program Files и общий кэш моделей в `C:\ProgramData\BarrensVoice` — с правом «изменение» для всех пользователей, которое выдаёт установщик с правами администратора. Без такого права второй пользователь не может обновить или докачать модель (кэш Hugging Face пишет файлы блокировки). Жёсткие ссылки тут не помогают: они работают только в пределах одного диска, а папка данных может быть на другом. Автообновление в Program Files — через UAC или отдельную службу.
- **Один движок для всех.** Если Piper (docs/piper.md) окажется не хуже F5, значение по умолчанию `"engine": "auto"` начнёт выбирать Piper и на NVIDIA — пользователи получат его обычным обновлением. Тогда сборки с CUDA и DirectML нужны только тем, кто сам выберет F5, и установщик становится маленьким. Значение по умолчанию хранить как `"auto"` и решать при запуске: `load_config` записывает значения по умолчанию в `config.json`, и новое значение иначе не дошло бы до старых установок.
